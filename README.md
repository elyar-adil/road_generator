# 路口工坊 · Intersection Studio

项目现在以 **可编辑 SD 路网 → HD 车道图 → 设施与街区 → 场景几何** 为城市生成主流程。
新建会进入城市模式；已有项目保持原来的类型，也可用“路口类型”切换城市、信号交叉口与环岛。

城市模式提供：

- 带种子的有机路网生长：河岸主干路、有限跨河桥梁、放射状旧城核心，以及受城区方向场和人口密度引导的次干路与支路。
- SD 节点拖拽、增删、Shift 连路；道路等级、正反向车道数和地面/上跨/下穿关系编辑。
- 同层交叉自动拆点，分层交叉保持独立；连通分量、重复道路、短边及纵坡检查。
- 从 SD 派生有向车道、左右转/直行连接、上下游关系、路口边界、桥面厚度与避让道路的桥墩。
- 从路网面提取街区，半平面退界、BSP 地块细分、临街建筑与多中心高度分布。
- SD、HD、三维、语义类别四种视图。建筑外墙贴图、屋顶、树枝与叶片均用程序生成。
- 保存可编辑项目（v4，兼容旧版）、导出 GLB/PNG，以及含 SD/HD、地块、建筑轮廓、种子和语义字典的场景 JSON。

在 SD 编辑模式下拖动节点；双击空白添加节点；按住 Shift 依次点击两个节点连接道路；点击道路编辑属性。
切到 HD 会聚焦选中的节点或中心附近的路口。修改城市边长、街区尺度或道路曲折度后，点击“生成新 SD 路网”应用；该操作可撤销。
修改已有道路请使用道路属性面板。场景种子控制细节，新 SD 路网生成时也使用该种子。

这版已用方向场与局部约束生长替换了网格生成器，提供河谷城市这一种地理基线，尚未覆盖真实城市的所有形态。桥梁和基础交叉口已从 SD 派生；完整立交形式选择、独立匝道子图、隧道洞口与地形开挖、连续三维地形代价、交通/物理/传感器仿真尚未实现。
HD 目前是项目自身的数据格式，没有宣称兼容 OpenDRIVE、Lanelet2 或生产级自动驾驶地图。
详细的数据契约与扩展位置见 [架构说明](docs/architecture.md)。

以下为保留的局部路口编辑器功能。

一个完全运行在浏览器中的程序化三维路口设计工具。项目由原始的
`intersection_generator.html` 原型扩展而来，保留了道路、路沿、车道线、导向箭头、
信号灯、护栏、建筑和树木的生成能力，并加入了完整的项目工作流。

## 功能

- 两种路口类型：信号交叉口与环岛（环流道 + 中心岛 + 分道岛，含让行虚线、
  让行三角、逆时针环流导流箭头与入口人行横道，无信号）
- 2–8 个道路分支，可分别设置角度、进出车道、中央分隔和护栏
- 五种拓扑预设、随机生成和可复现的场景种子
- 3D 透视与正交俯视两种视图
- 可开关的车道级拓扑中心线叠加（3D 与俯视均可见），按直行/左转/右转着色
- 可开关的「分流/合流演示」图层，演示 3→2→3 走廊、人行道与路灯的复用抽象
- 交通信号动画、速度控制和暂停
- 可按进口道配置单/双左转弧形待转区或直行待行区标线
- 右转设施支持既有最右侧车道直接连接、近端分流右转车道、远端分流右转辅路（Slip lane）；分流/辅路的三角区域可选绿化岛或导流线区
- 右转车道支持两种车道方案：方案1「最外侧车道为右转专用道」（箭头右转）或方案2「主线直行 + 独立右转分支」，箭头/中心线/导流区三者自动保持一致
- 可配置路口核心尺寸；默认按紧凑型城市路口的 30–42 m 三角分布生成
- 浏览器自动保存、撤销/重做、参数校验与实时统计
- 项目 JSON 导入/导出、PNG 截图、GLB 三维模型导出
- 响应式桌面/移动端界面
- 纯本地 Three.js 依赖，不依赖 CDN

## 架构：两层模型

场景生成遵循「两层模型 + 派生层」管线，所有细节从车道拓扑派生而来：

```text
Layer 1  ROAD（road-model.js）     每条道路的几何（横断面/朝向/角点）与
                                   网络连通性（直行/左转/右转目标、右转设施）
        ↓
Layer 2  LANE（lane-topology.js）  显式车道图：进/出车道端点、车道间转向连接、
                                   专用道中心线（单一事实来源，驱动箭头与拓扑叠加）
        ↓
派生层   lane-derive.js            纯数据：路面/中央分隔/车道线/箭头/导流区/
                                   待转区/人行道/护栏/停止线/斑马线/路灯/建筑…
        ↓
渲染层   render.js                 THREE 网格（颜色/高度/材质）
```

`main.js` 只负责场景初始化、UI 与动画；`regenerate` 简化为「模型 → 车道图 →
派生 → 渲染」四步。派生层与渲染层解耦：任何道路类型（分流/合流/未来的立交
匝道）都先产出纯数据，再由渲染层画出来，可单测、可复用。

## 开发

需要 Node.js 20.19+ 或 22.12+。

```bash
npm install
npm run dev
```

浏览器打开终端显示的本地地址（默认 `http://127.0.0.1:5173`）。

## 构建与测试

```bash
npm test
npm run build
npm run preview
```

浏览器交互与导出回归：

```bash
npm run test:e2e
```

Windows 默认使用已安装的 Edge；其他平台先运行 `npx playwright install chromium`。
也可通过 `PLAYWRIGHT_CHANNEL` 选择已安装的浏览器。测试会启动开发服务器，并将各层截图写入 `artifacts/`。

生产文件生成在 `dist/`。由于项目使用 ES 模块，开发版本和构建版本都应通过 HTTP
服务器访问，不建议直接双击 `index.html`。

## 项目结构

```text
intersection-generator/
├─ index.html             应用界面与无障碍结构
├─ src/
│  ├─ main.js             场景初始化、UI、动画（薄壳；regenerate 为四步管线）
│  ├─ project-store.js    自动保存、下载与历史记录
│  ├─ state.js            项目模型、校验、统计与序列化
│  ├─ geometry.js         共享 2D 向量/曲线/虚线/offset/fillet 原语（全项目唯一来源）
│  ├─ frame.js            道路坐标系：直线射线/折线中线两种内核的 (u,s)→世界平面映射（环岛/匝道的地基）
│  ├─ roundabout.js       环岛几何内核：布局规则、环流道环面、分道岛透镜多边形（纯数据）
│  ├─ road-model.js       层1 ROAD：道路几何、连通性、右转设施（纯数据）
│  ├─ lane-topology.js    层2 LANE：显式车道图与车道中心线（纯数据）
│  ├─ lane-derive.js      派生层：从道路模型+车道图派生全部标线/设施（纯数据）
│  ├─ render.js           渲染层：派生数据 → THREE 网格（含主题）
│  ├─ segment.js          道路段复用抽象：车道束横断面、分流/合流渐变、人行道边界、路灯布点
│  ├─ road-movements.js   转向分类与车道转向分配（箭头/拓扑单一事实来源）
│  ├─ right-turn.js       右转/分流/汇流设施的纯几何生成器
│  ├─ waiting-area.js     左转/直行待转区几何（复用 geometry.js）
│  ├─ state.test.js       状态层单元测试
│  └─ styles.css          响应式视觉系统
├─ package.json
└─ vite.config.js
```

车道级拓扑（lane graph）与道路段（segment）抽象是本项目的通用地基：分流/合流
渐变、人行道、路灯都建立在同一套可复用原语之上，可继续向立交桥/匝道等任意道路
类型扩展。

## 项目文件

“保存项目”会下载带格式名和版本号的 JSON 文件。导入时会校验文件类型、版本、道路数量、
车道范围和分支最小夹角。浏览器中的自动保存仅保留最近状态；需要长期归档时请导出 JSON。

GLB 导出包含当前生成的道路与场景对象，不包含编辑器界面和地面背景。
